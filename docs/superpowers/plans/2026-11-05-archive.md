# Archive Implementation Plan (Build Step 5 of 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From the page, Colin queues files and folders for the homelab,
reviews the exact plan, and confirms. Each item is copied to the Seagate
archive and checked with SHA-256 on both ends. Only an item whose copy
matches moves to the Mac's Trash.

**Architecture:** Five new modules in the `actions` package.
- `archive_config` loads a git-ignored `local/archive.toml`.
- `remote` builds every SSH command from a fixed allowlist, tries hosts in
  order, and checks the host's identity and the Seagate mount.
- `manifest` lists and hashes a local item and parses the remote listing.
- `archive` runs one batch: preflight once, then copy, compare, move into
  place, set owner and mode, and Trash the local copy.
- `build_plan` gains an `archive` action.

The server's existing plan and run endpoints take
`action: "archive"` and a `location`. The page gains a second queue and an
Archive tab built from the Delete tab's parts. Tests never touch the real
homelab: SSH and rsync go through an injectable runner.

**Tech Stack:** Python 3.12 standard library (`tomllib`, `hashlib`, `shlex`).
On the Mac: `/usr/bin/ssh` and `/usr/bin/rsync` (openrsync, protocol 29). On
the homelab: rsync 3.2.7, GNU coreutils `sha256sum -z`, `findmnt`, and `sudo -n`.

**Spec:** `docs/superpowers/specs/2026-11-05-storage-explorer-design.md`,
sections 6.4, 8.1, 8.3 (credentials updated 2026-11-05: Colin chose the
existing `opencode` setup), and 9. Builds on steps 1–4 and 6.

## Global Constraints

- **Nothing local is touched unless the remote copy is proven.** An item moves
  to the Trash only after every regular file's SHA-256, every link target, and
  every folder match on both ends. Any mismatch or error leaves the local item
  as it was.
- **The tool never removes anything on the homelab.** The remote commands are
  limited to the allowlist in Task 1. `rm` is not on it, and neither is `find`
  with `-delete`. A failed copy stays in the batch's `.incoming/` folder and
  is reported.
- **Connection rules (spec 8.3):**
  - Try the configured hosts in order. Move on only on these errors: DNS
    lookup failed, connection refused, connection timed out, no route, or
    network unreachable.
  - Stop on an authentication failure, a host-key problem, or a `hostname`
    that differs from `expected_hostname`.
  - Always use `-o IdentitiesOnly=yes -o BatchMode=yes`, and never weaken
    host-key checking.
- **Storage guard (spec 8.3):**
  - Before writing, `findmnt --mountpoint <mount_point>` must report the
    configured filesystem UUID.
  - Free space must be at least the batch total plus 1 GiB.
  - The guard runs once at the start and again before each item.
- **No hosts or UUIDs in the repository.** They live only in
  `local/archive.toml`, which git ignores. The committed example
  `archive.example.toml` uses placeholders.
- **Everything else is as before:**
  - Standard library only; `uv`, pytest, ruff (format first, then check), and
    strict mypy.
  - No `sudo` on the Mac.
  - Commit identity and trailer as in previous plans.

## Decisions in This Plan (mine, flagged for Colin's review)

- **Batch folder:** `<location>/<UTC timestamp>/` instead of `<date>/`, so
  two runs on the same day never collide.
- **Layout inside the batch:** each item keeps its original path. For
  example, `~/Downloads/x` lands at `<batch>/Users/colinwhite/Downloads/x`.
  - Items are first copied to `<batch>/.incoming/<n>/`, a destination name
    that never passes through a shell. Only then are they moved into place,
    with a command quoted by `shlex.join`.
- **Batch files:**
  - `MANIFEST.json` (path, bytes, SHA-256) and `README.md` (how to copy items
    back) sit in the batch folder.
  - The same manifest is kept under `reports/archives/`.
- **Ownership:** at the end, the batch becomes `owner:group` from the config,
  with folders `2770` and files `660`. That matches the homelab repository's
  archives.
- **Archive location field:** editable, but the server accepts only a
  normalized path under the configured `allowed_root`.
- **What is not archived:**
  - Docker and Homebrew items, which are refused.
  - Items whose path contains a control character.
  - Items holding sockets, FIFOs or device files.
  - macOS extended attributes and Finder tags. openrsync does not copy them,
    and the README says so.
- **Queues:** an item sits in at most one queue. Adding it to one removes it
  from the other.
- **Target mode stays on the Delete queue.** An archive-aware target mode is
  a later task.

## Review Focus

1. **Odd names.** Spaces, quotes, `$`, backticks, a leading `-`, non-ASCII
   characters, and newlines inside a folder's file names. The copy matches
   byte for byte, or the item is refused with a reason. It never ends up
   half-moved (Tasks 2 and 4, and the Task 6 real run).
2. **The Seagate is missing, or the wrong host answers.** The disk is not
   mounted or has a different UUID. `hostname` differs. The host key is
   unknown or changed. Nothing is written, nothing is trashed, and the page
   says why (Tasks 1 and 4).
3. **A file changes during the copy** (a growing log). The checksum
   mismatches, so the local copy is kept and the remote copy stays in
   `.incoming/`, reported (Task 4).
4. **The connection drops partway through a batch.** Items already verified
   are finished and trashed. The failed item and everything after it stay
   local (Task 4).
5. **Location tricks and mixed queues.** A location with `..`, `//`, or a path
   outside `allowed_root`. A Docker item in the Archive queue. The same item
   queued in both tabs. Each is refused or prevented (Tasks 3 and 5).

### Task 1: Configuration and the remote layer

**Files:**
- Create: `archive.example.toml`, `actions/archive_config.py`, `actions/remote.py`.

- Tests: `tests/actions/test_archive_config.py`, `test_remote.py`, `tests/test_cli.py`.

**Interfaces (produces):**
```python
# archive_config.py
DEFAULT_CONFIG_PATH: Final = Path("local/archive.toml")
@dataclass(frozen=True)
class ArchiveConfig:
    hosts: tuple[str, ...]; user: str; key: Path; expected_hostname: str
    mount_point: str; fs_uuid: str; allowed_root: str; location: str
    owner: str; group: str
def load_config(path: Path) -> ArchiveConfig          # ValueError with a plain message
def check_location(config: ArchiveConfig, location: str) -> str | None   # None = OK, else the reason

# remote.py
REMOTE_PROGRAMS: Final = frozenset({"hostname", "findmnt", "df", "install", "mkdir",
                                     "mv", "chown", "find", "rmdir", "sh"})
type TimedRunner = Callable[[Sequence[str], float], CommandResult]
def ssh_runner(args: Sequence[str], timeout: float) -> CommandResult   # stdin=DEVNULL, new session
class RemoteError(Exception): ...                    # .message is user-facing
@dataclass(frozen=True)
class Remote:
    config: ArchiveConfig; host: str; run: TimedRunner
    def ssh_args(self, argv: Sequence[str]) -> list[str]     # sudo -n prefixed except hostname
    def call(self, argv: Sequence[str], timeout: float = 60) -> CommandResult
    def rsync_args(self, source: str, dest_dir: str) -> list[str]
def connect(config: ArchiveConfig, run: TimedRunner) -> Remote          # host order + identity
def check_storage(remote: Remote, need_bytes: int) -> None              # raises RemoteError
```

`load_config` rules:
- Every field is required.
- `hosts` must be a non-empty list of strings.
- `key` expands `~`.
- `mount_point`, `allowed_root` and `location` must be absolute and
  normalized: no `.` or `..` parts, no `//`, and no trailing `/`.
- `allowed_root` must lie under `mount_point`, and `location` under
  `allowed_root`.

`check_location` uses the same rules. It also refuses characters outside
`[A-Za-z0-9._/-]` (no spaces). The rsync destination is built from the
location, and it never passes through a shell unquoted.

`ssh_args`:
- Returns `["/usr/bin/ssh", "-o", "IdentitiesOnly=yes", "-o",
  "BatchMode=yes", "-o", "ConnectTimeout=10", "-i", str(key),
  f"{user}@{host}", "--", shlex.join(["sudo", "-n", *argv])]`.
- `hostname` goes without `sudo -n`.
- `call` raises `ValueError` when `argv[0]` is not in `REMOTE_PROGRAMS`.
- `sh` is allowed only with the exact `LIST_SCRIPT` from Task 2.

`rsync_args` returns:
`["/usr/bin/rsync", "-a", "--rsync-path=sudo -n rsync", "-e",
"/usr/bin/ssh -o IdentitiesOnly=yes -o BatchMode=yes -i <key>", "--", source,
f"{user}@{host}:{dest_dir}/"]`. `dest_dir` must match `^[A-Za-z0-9._/-]+$`,
otherwise it raises `ValueError`.

`connect`:
- Runs `hostname` on each host in order.
- Exit 255 with stderr containing "Could not resolve hostname", "Connection
  refused", "timed out", "No route to host", or "Network is unreachable"
  means: try the next host.
- Any other failure raises `RemoteError`. "Permission denied" →
  "The homelab refused the SSH key." "Host key verification failed" or
  "REMOTE HOST IDENTIFICATION HAS CHANGED" → "The homelab's host key is
  unknown or changed; check it by hand before archiving."
- A `hostname` other than `expected_hostname` raises "Unexpected host <x>".

`check_storage`:
- Runs `findmnt -no UUID --mountpoint <mount_point>` and
  `df -B1 --output=avail -- <mount_point>`.
- Raises "The archive disk is not mounted" (empty output), "The archive disk
  is not the expected one", or "Not enough free space on the homelab (<x>
  free, <y> needed)".

CLI: `storage-cleanup archive check [--config PATH]`.
- Loads the config, connects, and runs `check_storage(remote, 0)`.
- Prints the host used and the free space, and exits 0. On error, prints the
  message and exits 2.
- Read-only.

- [ ] **Step 1: Failing tests:**
  - Config: a valid file loads; each missing field; `location` outside

  - `check_location`: a quote or a newline is refused.
  - `ssh_args`: exact argv. A path with spaces, `'`, `$`, and a leading `-`

  - `call`: `rm` and `sh -c 'other'` raise.
  - `connect`: the first host fails DNS and the second answers, so the second

### Task 2: Manifests

**Files:** create `actions/manifest.py`; test `tests/actions/test_manifest.py`.

**Interfaces (produces):**
```python
@dataclass(frozen=True)
class Manifest:
    files: dict[str, tuple[int, str]]   # relative path -> (bytes, sha256 hex)
    links: dict[str, str]               # relative path -> link target
    dirs: frozenset[str]                # relative paths
# Paths in every Manifest are relative to the folder that CONTAINS the item,
# so they start with the item's own name (a file item is just {"name": ...}).
LIST_SCRIPT: Final = ('cd -- "$1" && find . -mindepth 1 \\( -type d -printf "D\\0%P\\0" \\) '
                      '-o \\( -type l -printf "L\\0%P\\0%l\\0" \\) '
                      '-o \\( -type f -printf "F\\0%P\\0%s\\0" \\) '
                      '&& printf "H\\0" && find . -type f -exec sha256sum -z -- {} +')
class UnsupportedItem(Exception): ...    # socket / FIFO / device inside the item
def local_manifest(path: Path) -> Manifest
def parse_listing(data: bytes) -> Manifest
def compare(local: Manifest, remote: Manifest) -> list[str]   # [] = identical; else short problems
def manifest_to_json(m: Manifest, base: str) -> list[dict[str, JsonValue]]
```

Behaviour:
- `local_manifest` walks with `os.scandir` and `lstat`, never following
  links. It hashes regular files in 1 MiB chunks.
- A file item becomes `{"<name>": (size, hash)}`, and a folder item lists
  `<name>` in `dirs` plus everything under it.
- Names are kept as raw strings, using `os.fsdecode` with surrogateescape.
- The remote listing runs as `sh -c LIST_SCRIPT sh <batch>/.incoming/<n>`,
  the folder that holds the copied item.
  - Records before the `H` marker are `D`, `L` and `F` records.
  - After the marker, `sha256sum -z` prints `hash  ./path\0` per file, in any
    order, without escaping.
  - The parser pairs each hash with its `F` record by path. A file with no
    hash, or a hash with no file, is a parse error that `compare` reports as
    a problem.
- `compare` reports at most 5 problems, each naming the path: "missing on
  the homelab", "size differs", "checksum differs", "link differs", or
  "extra on the homelab".

### Task 4: Running an archive batch

**Files:**
- Create: `actions/archive.py`.
- Modify: `web/server.py` (replace the 501).
- Test: `tests/actions/test_archive.py`.

**Interfaces:**
```python
ARCHIVE_TIMEOUT_SECONDS: Final = 6 * 3600     # per rsync
FREE_MARGIN_BYTES: Final = 1024**3
def run_archive(plan: ActionPlan, scan: Scan, *, config: ArchiveConfig,
                remote_runner: TimedRunner, runner: Runner, brew_prefix: Path | None,
                log_dir: Path, manifest_dir: Path, now: Callable[[], float] = time.time) -> ActionResult
```

Order of operations (pinned):
1. Write the log (state `running`).
2. `connect`, then `check_storage(total + FREE_MARGIN_BYTES)`. A
   `RemoteError` here marks every entry `skipped` with its message, and
   nothing is written remotely.
3. Make the batch folder:
   `install -d -o O -g G -m 2770 -- <location> <batch> <batch>/.incoming`,
   where batch = `<location>/<YYYYmmddTHHMMSSZ>`.
4. For each entry, in order:
   - `verify_entry`, then `check_storage(entry size)`.
   - `install -d ... <batch>/.incoming/<n>`.
   - rsync the local path into `.incoming/<n>` (timeout
     `ARCHIVE_TIMEOUT_SECONDS`).
   - `local_manifest`, then the remote listing of
     `.incoming/<n>/<basename>`, then `compare`.
   - On any problem: status `failed`, with the first problem and "the
     homelab copy is in <path>". Nothing local changes. Go to the next
     entry, unless the problem is a lost connection: then mark the rest
     `skipped` with "Connection lost".
   - On a match:
     - `mkdir -p -- <parent of final>`.
     - `mv -n -T -- <incoming item> <final>`. If `<final>` already exists,
       the item fails.
     - `rmdir -- <incoming/n>`.
     - `recheck_path`, then `/usr/bin/trash`, as in `run_plan`.
     - Status `done`: "Copied to the homelab, checked, and moved to the
       Trash."
5. Write `MANIFEST.json` and `README.md` to a temp folder and rsync them to
   `<batch>`. Save the same manifest to
   `manifest_dir/<batch-name>.json`.
6. Finish ownership and mode:
   - `chown -R -- O:G <batch>`.
   - `find <batch> ( -type d -exec chmod 2770 {} + ) -o ( -type f -exec chmod 660 {} + )`.
     `chmod` runs only inside `find -exec`. The test that checks every
     remote argv also checks that every `find -exec` runs only `chmod` or
     `sha256sum`.
   - Then `rmdir -- <batch>/.incoming`. Ignore a failure here: it means a
     failed item is still inside.
7. Write the log (state `finished`). `archived_bytes` and
   `moved_to_trash_bytes` both count `done` entries, and `archive_batch` is
   set.

The README's restore line is `rsync -a --rsync-path="sudo -n rsync" -e "ssh -i <key>" <user>@<host>:'<final>' '<original parent>/'`.
