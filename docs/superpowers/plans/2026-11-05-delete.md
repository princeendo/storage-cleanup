# Delete Implementation Plan (Build Step 4 of 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From the page, Colin can queue items, review exactly what will
happen, and remove them. By default they move to the Trash. Permanent
deletion, Docker images, Docker build cache, and Homebrew packages are also
supported, each labelled with how to undo it. The server re-checks every item
just before acting, writes a log, and reports space freed and space still
waiting in the Trash.

**Architecture:** A new `actions` package does the work.
- `build_plan` turns item IDs into a plan, refusing what may not be removed.
- `verify_entry` re-checks one entry against the live filesystem.
- `run_plan` executes, records each result, and writes the log.
- `empty_trash` empties the Trash through Finder.

The server gains `POST` endpoints that rebuild the plan themselves (they never
trust a plan from the browser). A run requires the fingerprint of the plan the
user reviewed. The page gains a queue, checkboxes, a Delete tab, confirmation
dialogs, and a results view. Commands go through the injectable `Runner`, so
tests never touch the real Trash, Docker, or Homebrew.

**Tech Stack:** Python 3.12 standard library; `/usr/bin/trash` (built into
macOS, keeps Finder's "Put Back"); `osascript` for Empty Trash; `docker` and
`brew` CLIs. The page uses plain ES modules, as before.

**Spec:** `docs/superpowers/specs/2026-11-05-storage-explorer-design.md`
(sections 6.3, 6.4, 8.1, 8.2, 9). Builds on steps 1–3.

## Global Constraints

- **Tests never remove anything real.** Filesystem tests use `tmp_path`.
  `trash`, `docker`, `brew`, and `osascript` go through `FakeRunner`. The
  single live check against the real Trash (Task 9) needs Colin's OK first.
- **Nothing happens without explicit confirmation of an exact plan.** The run
  endpoint takes `plan_id`, a SHA-256 of the plan's entries and methods. If the
  server's rebuilt plan differs, it answers `409` with "The plan changed; review
  it again."
- **Permanent delete** (spec 8.2) is off by default, switched on per run, and
  needs a second confirmation where the user types `delete permanently`. The
  server checks that phrase.
- **The Trash is the default** for files and folders.
- **Docker volumes, protected items, unknown items, and grouped (roll-up)
  rows are never acted on.** Roll-ups are expanded to their members in the
  browser.
- **Allowed roots.** An entry's path must lie under the scan's home folder,
  `/Applications`, or the Homebrew prefix, and must not be one of those roots.
- **Never follow symlinks** when checking or deleting. A symlink is removed as
  the link itself.
- **POST endpoints require all of these:** the session cookie, an `Origin` of
  `http://127.0.0.1:<port>` or `http://localhost:<port>`, the
  `Content-Type: application/json` header, and a body of 1 MB or less. Only one
  run at a time (a server-wide lock); a second concurrent run gets `409`.
- **Logs** go to `reports/actions/<UTC time>.json` (git-ignored).
- Python 3.12 standard library only; `uv`; pytest, ruff (format, then check),
  and mypy strict pass after every task. Commit identity and trailer as in
  previous plans.

## Review Focus

1. **The disk changed after the scan.** The item is gone, has grown or shrunk
   a lot, has been replaced by a symlink, or a Photos library or `.git`-less
   protected store has appeared inside it. The item is skipped with a reason and
   never forced (Task 3).
2. **A crafted request** from another page, without the reviewed `plan_id`,
   with permanent mode but not the phrase, or with IDs outside the scan. It gets
   rejected before anything runs (Task 6).
3. **A parent and its child both queued.** The child is refused as already
   covered, so nothing is attempted twice (Task 2).
4. **A partial failure halfway through** (one `trash` call fails, `brew`
   refuses a formula others depend on). Later items still run, every outcome is
   logged, and the page shows each result (Task 4).
5. **The page reloads or the user goes back.** The queue survives in
   `sessionStorage`, and a stale review cannot be confirmed (Tasks 6–8).

### Task 2: Action model and `build_plan`

**Files:** Create `src/storage_cleanup/actions/__init__.py`, `model.py`, `plan.py`; test `tests/actions/test_plan.py` (+ `__init__.py`).

**Interfaces:**

```python
class Method(StrEnum):
    TRASH = "trash"; DELETE = "delete"
    DOCKER_IMAGE = "docker-image-rm"; DOCKER_BUILD_CACHE = "docker-builder-prune"
    BREW_FORMULA = "brew-uninstall"; BREW_CASK = "brew-uninstall-cask"

@dataclass(frozen=True)
class PlanEntry:
    item_id: str; name: str; path: str | None; size_bytes: int
    method: Method; undo: str; warnings: tuple[str, ...]
@dataclass(frozen=True)
class Refusal:
    item_id: str; name: str; reason: str
@dataclass(frozen=True)
class ActionPlan:
    scan: str; permanent: bool
    entries: tuple[PlanEntry, ...]; refused: tuple[Refusal, ...]
    total_bytes: int; trash_bytes: int; freed_bytes: int   # trash vs freed now
def plan_id(plan: ActionPlan) -> str      # sha256 over scan + permanent + sorted (item_id, method)
def plan_to_json(plan: ActionPlan) -> dict[str, JsonValue]   # includes "plan_id"

def removal_method(item: Item, permanent: bool) -> Method | None   # None = not removable here
def build_plan(scan: Scan, scan_name: str, item_ids: Sequence[str], *, permanent: bool) -> ActionPlan
```

Methods by kind:
- `docker-image` → `DOCKER_IMAGE`; `docker-build-cache` → `DOCKER_BUILD_CACHE`.
- `brew-formula` → `BREW_FORMULA`; `brew-cask` → `BREW_CASK`. A path inside
  the Cellar is never trashed directly.
- Any other item with a path → `TRASH`, or `DELETE` when `permanent`.

Refusals, each with its own sentence:
- unknown ID;
- protected (`"Protected: <reason>"`);
- `docker-volume` ("Docker volumes can hold data that cannot be recreated; remove them with Docker yourself");
- `docker-total` and virtual items without a method ("Not removable from the page");
- an ancestor is also in the request ("Already included in <ancestor name>");
- a duplicate ID.

Undo text:
- `TRASH`: "Put Back from the Trash in Finder."
- `DELETE`: "Cannot be undone."
- Docker image: "Pull or build the image again."
- Docker build cache: "Rebuilt the next time images are built."
- Homebrew: `"Reinstall with brew install <name>"` (or `--cask`).

Warnings:
- a `repo` item that is `dirty` or has `unpushed_commits`;
- a `repo` with no remote ("No remote: this is the only copy");
- a `brew-formula` that is not a `leaf` ("Other formulae depend on this; Homebrew may refuse").

The totals split `trash_bytes` (`TRASH` entries) from `freed_bytes` (all others).

### Task 3: Re-verify each entry against the disk

**Files:** Create `src/storage_cleanup/actions/verify.py`; test `tests/actions/test_verify.py`.

**Interfaces:**

```python
SIZE_DRIFT_FRACTION: Final = 0.10
SIZE_DRIFT_MIN_BYTES: Final = 100 * 1024**2
def allowed_roots(scan: Scan, brew_prefix: Path | None) -> tuple[Path, ...]   # home, /Applications, brew prefix
def verify_entry(entry: PlanEntry, scan: Scan, *, brew_prefix: Path | None) -> str | None
    # None = safe to act; else a sentence why it is skipped
```

Checks for path entries, in order:
1. `os.lstat` succeeds ("No longer exists").
2. The path is under an allowed root and is not a root ("Outside the folders this tool may change").
3. `protected_reason(path, home)` ("Protected: …").
4. The path contains a protected store. Use `containing_reason` over the fixed
   home stores, existing `~/Pictures/*.photoslibrary`, and any
   `*.photoslibrary`, `*.sparsebundle`, or `*.backupbundle` found by a bounded
   walk (depth 3) inside the entry. A `.git` folder inside does not count.
5. If the scan recorded it as a folder and the disk now has a symlink, or the
   other way around: "Changed type since the scan".
6. Size drift. Re-measure (allocated); skip when the change is larger than
   both `SIZE_DRIFT_FRACTION` of the scanned size and `SIZE_DRIFT_MIN_BYTES`:
   `"Changed since the scan (was X, now Y); rescan first"`.

Non-path entries (Docker, Homebrew) are verified by their command's own result
in Task 4.

### Task 4: Run a plan and log it

**Files:** Create `src/storage_cleanup/actions/run.py`; test `tests/actions/test_run.py`.

**Interfaces:**

```python
@dataclass(frozen=True)
class EntryResult:
    item_id: str; name: str; path: str | None; method: Method
    status: str        # "done" | "skipped" | "failed"
    detail: str        # reason or command error (first 300 chars)
    size_bytes: int
@dataclass(frozen=True)
class ActionResult:
    plan_id: str; permanent: bool; started_at: str; finished_at: str
    results: tuple[EntryResult, ...]
    free_before: int; free_after: int
    moved_to_trash_bytes: int; freed_bytes: int
    log_path: str

def delete_path(path: Path) -> None
    # lstat; symlink or file -> os.unlink; directory -> shutil.rmtree(path) (refuses symlinked roots)
def run_plan(plan: ActionPlan, scan: Scan, *, runner: Runner, brew_prefix: Path | None,
             log_dir: Path, now: Callable[[], float] = time.time) -> ActionResult
```

Per entry: `verify_entry`. A reason means `skipped`. Otherwise execute:

| Method | Command / call | Done when |
| --- | --- | --- |
| `TRASH` | `["/usr/bin/trash", path]` | exit 0 **and** `lstat(path)` now raises `FileNotFoundError` |
| `DELETE` | `delete_path(Path(path))` | no exception and the path is gone |
| `DOCKER_IMAGE` | `["docker", "image", "rm", <details.image_id>]` | exit 0 |
| `DOCKER_BUILD_CACHE` | `["docker", "builder", "prune", "--force"]` | exit 0 |
| `BREW_FORMULA` | `[<prefix>/bin/brew, "uninstall", name]` | exit 0 |
| `BREW_CASK` | `[<prefix>/bin/brew, "uninstall", "--cask", name]` | exit 0 |

Anything else becomes `failed` with stderr or the exception text. Continue to
the next entry, always. `free_before` and `free_after` come from
`shutil.disk_usage(home)`. Byte totals count only `done` entries. Write the log
JSON (plan, results, free space) atomically to `log_dir`, and put its path in
the result.

### Task 6: Server endpoints

**Files:** Modify `src/storage_cleanup/web/server.py`; test `tests/web/test_server.py`.

```python
POST /api/plan         {"item_ids": [...], "permanent": bool}
    -> 200 plan_to_json(plan)                          (no side effects)
POST /api/run          {"item_ids": [...], "permanent": bool, "plan_id": str, "confirm": str | null}
    -> 200 result JSON | 409 plan changed / run in progress | 400 bad request
POST /api/empty-trash  {"confirm": "empty trash"}
    -> 200 {"ok": bool, "message": str}
```

`make_server` gains `runner: Runner = subprocess_runner` and
`brew_prefix: Path | None` (default: detected as in `cli.default_context`).
The log dir is `<scan file>/../../actions`.

`/api/run` checks, in order:
1. JSON shape (`400`).
2. Rebuild the plan from the latest scan file.
3. `plan_id` matches (`409` "The plan changed; review it again.").
4. `permanent` requires `confirm == "delete permanently"` (`400`).
5. Acquire the lock (`409` "Another run is in progress.").
6. `run_plan`.

`/api/empty-trash` requires `confirm == "empty trash"`.

POST guards (all endpoints): cookie, Host, `Origin` in
`{http://127.0.0.1:<port>, http://localhost:<port>}` (missing or other gives `403`),
`Content-Type` starting with `application/json` (`415`), and `Content-Length`
of 1,048,576 or less (`413`). GET stays as before. Other methods remain `405`.
