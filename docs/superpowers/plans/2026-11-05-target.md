# Target Mode and Growth Implementation Plan (Build Step 6 of 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Colin sets a goal, either "get me to 15% free" or "free 10 GB". The
page checks the best-scoring recommendations until the goal is met, and a
"Path to your target" chart shows progress live. Separately, a "What grew
since last time" card on the Overview compares this scan with the previous
one and shows a trend of used space across saved scans.

**Architecture:** Python prepares the data.
- `target_candidates` is the ordered list of removable, non-overlapping
  recommendations.
- `growth` holds the changes between this scan and the previous one.
- `history` holds used and free space over saved scans, cached by file
  modification time.

The browser does the live arithmetic only: bytes still needed for the goal,
and a greedy fill in candidate order. Checking items uses the existing queue,
so the confirmation flow from step 4 is unchanged. Target mode never removes
anything by itself.

**Tech Stack:** Python 3.12 standard library; existing page and ECharts.

**Spec:** `docs/superpowers/specs/2026-11-05-storage-explorer-design.md`
(6.2 insights 3 and 5, 6.3 target mode, 8.2 "met once the Trash is emptied"
versus "met now", and the snapshot note). Builds on steps 1–4.

## Global Constraints

- **Read-only additions.** Target mode only adds to the Delete queue; removing
  still needs the step 4 review and confirmation (spec 9: "Target mode
  pre-checks items, but the final confirmation is still the user's choice").
- **Two numbers, kept separate:** "met now" counts space freed immediately
  (Docker, Homebrew, or permanent delete), and "met once the Trash is emptied"
  counts space moved to the Trash. When the scan saw local snapshots, the page
  adds: "Snapshots may keep some space in use until macOS removes them."
- **Growth compares measured items only:** by item ID, path items only, and
  changes of at least `GROWTH_MIN_BYTES = 100 MiB`.
- **Charts follow the dataviz skill.** Load it before Tasks 3–4. A change in
  disk use is not a status, so no good/bad colors: use ▲/▼ text with primary
  ink.
- **Everything as before:** standard library only, `uv`, pytest, ruff (format,
  then check), and mypy strict. Commit identity and trailer as in previous
  plans.

## Review Focus

1. **Goal already met, or impossible.** The goal is already met (needed ≤ 0);
   the candidates add up to less than needed; the percent box is empty, 0, 100,
   or not a number. The page explains each case and never queues anything
   unasked (Task 3).
2. **Overlap.** A folder and a file inside it are both recommended. The fill
   takes only the folder, and the bytes are counted once (Task 1).
3. **Rescan between two scans with renamed or vanished items.** Items present
   in only one scan show as "new" or "gone" when they are large enough. Totals
   never go negative (Task 2).
4. **Many saved scans,** or unreadable or old-schema scan files in the folder.
   The history skips them, and the cache stays bounded (Task 2).
5. **Changing the queue by hand after a fill.** The chart and the "met" text
   follow the actual queue, not the last fill (Task 3).

### Task 2: Growth and history

**Files:** Create `web/growth.py`; modify `web/views.py`, `web/server.py`; tests `tests/web/test_growth.py`, `tests/web/test_server.py`.

```python
GROWTH_MIN_BYTES: Final = 100 * 1024**2
GROWTH_ROWS: Final = 8
SHRINK_ROWS: Final = 5
HISTORY_LIMIT: Final = 60

def growth(scan: Scan, previous: Scan) -> dict[str, JsonValue]
    # {"previous_created_at", "used_change", "grew": [...], "shrank": [...]}
    # row: {item_id, name, path, before, after, change, status: "changed"|"new"|"gone"}
def history(scan_paths: Sequence[Path]) -> list[dict[str, JsonValue]]
    # [{created_at, used_bytes, free_bytes}] oldest first, at most HISTORY_LIMIT newest;
    # unreadable files skipped; cached by (path, mtime_ns, size) in a module dict capped at 2*limit
```

Choosing rows:
1. Take the changes of path items that appear in either scan, keyed by item
   ID, where `abs(change) >= GROWTH_MIN_BYTES`.
2. Drop an item when a descendant in the set explains 80% or more of its
   change (prefer the more specific item), and drop items under the same
   ancestor beyond that rule. Ancestry is by path prefix.
3. Show the top `GROWTH_ROWS` that grew and the top `SHRINK_ROWS` that shrank.

`build_view(scan, now, findings, note, previous=None, history=None)` adds
`"growth"` (`None` without a previous scan) and `"history"`.
`load_view` finds the previous scan with
`store.previous_scan(scan_path.parent, scan_path)` (an unreadable previous scan
is skipped) and the history from the `*.json` files in the scan's folder.

- [ ] **Step 1: Failing tests:**
  - grown, shrunk, new, and gone rows;
  - the 100 MiB threshold;
  - a nested child preferred over a parent it explains;
  - `used_change` matches the difference in disk use;
  - history order, limit, a broken file skipped, the cache reused (patch
    `scan_from_json` to count calls);
  - `load_view` with two scans gives growth, and with one gives `None`.
- [ ] **Step 2–4:** implement, then run all checks.
- [ ] **Step 5: Commit** `feat(web): compare with the previous scan and keep a history`.

Controls in one row above the Recommendations table:
- Goal: "Reach [15] % free" or "Free up [10] GB" (a segmented choice and a
  number field; 15% by default; the value is remembered in `localStorage` with
  try/catch).
- The button **Check the best items**: adds `fill(...)` to the queue (merging,
  never removing what the user queued).
- A sentence:
  - "You have X free (Y%). Reaching Z% needs N more."
  - "Already met."
  - "Even everything recommended (M) falls short by K."

The chart is one horizontal stacked bar on the disk's total-size scale (dataviz:
thin marks, legend, hover tooltips). Its segments are:
- current free space (neutral);
- queued items that free space now (`--series-1`);
- queued items that wait in the Trash (`--series-1` with the hatched texture
  from the dataviz texture rule, or a lighter step, plus a label);
- a dashed marker line at the target, labelled with the target.

Under the chart: "Met now", "Met once you empty the Trash", or "Not met yet:
N to go". Add the snapshot sentence when `overview.local_snapshots > 0`. The
chart and text update on every queue change.
