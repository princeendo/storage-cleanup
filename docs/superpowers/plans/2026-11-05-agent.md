# Agent Playbook and Recommendations Implementation Plan (Build Step 3 of 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any coding agent can follow `AGENT_PLAYBOOK.md` to study a scan and
write a validated findings file. The page shows the agent's headline cards and
a Recommendations tab ranked by score. Without an agent, rule-based
recommendations still fill the tab.

**Architecture:** Three new Python modules. `scan/recommend.py` holds the
score formula and the rule-based recommendations. `findings.py` holds the
findings file format, its validator, and where findings live.
`web/recommendations.py` merges rule and agent recommendations, rolls siblings
up, and produces page data. Two new commands help agents without
overflowing their context: `inspect` answers focused questions about a scan
(scan files are about 800 KB), and `findings check` validates what the agent
wrote. The page reads everything from `/api/view` as before.

**Tech Stack:** Python 3.12 standard library; existing page (HTML, CSS, ES
modules, vendored ECharts).

**Spec:** `docs/superpowers/specs/2026-11-05-storage-explorer-design.md`
(sections 5, 6.1 "recommended to reclaim", 6.2 insight 1, 6.3, 7, 9). Builds on
the scanner plan (`2026-11-05-scanner.md`) and the page plan (`2026-11-05-page.md`).

## Global Constraints

- Python `>=3.12`, standard library only. Everything through `uv`; pytest,
  ruff (format, then check), and mypy strict pass after every task. Never pipe
  a check into `tail` inside an `&&` chain.
- Still read-only. No command or page action removes, moves, or changes
  anything. Queueing items for Archive or Delete arrives in build step 4. Until
  then the Recommendations tab shows proposed actions without checkboxes.
- The agent recommends and the user acts (spec section 5). Findings are
  untrusted input: validate them, drop anything invalid with a visible note,
  and render all agent text with `textContent` or `esc()`.
- **Protected items are never recommended.** The validator rejects them,
  `merge_recommendations` drops them, and rule-based recommendations skip them.
- Findings files live in `reports/findings/` (git-ignored). Each is named
  after its scan file: `reports/findings/<scan file name>`.
- Scores follow spec section 7: `score = 100 × confidence × g(bytes)`, where
  `g(b) = clamp((log2(b) − 12) / (35 − 12), 0, 1)`. That is 0 at or below
  4 KiB and 1 at or above 32 GiB.
- Commit identity `13876322+princeendo@users.noreply.github.com`; messages
  end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Hostile agent text.** A title, body, reason, or category name that holds
   HTML must render as text in the cards, the table, the tooltips, and the
   detail panel (Tasks 7–8).
2. **Findings that point at the wrong things.** An unknown item ID, a
   protected path, a confidence outside 0–1, an unknown action, or findings
   for a different scan must be rejected with a clear message and never shown
   as a recommendation (Tasks 2, 3, 5).
3. **Nested recommendations.** A folder and a file inside it can both be
   recommended. "Recommended to reclaim" must count the bytes once (Task 3).
4. **A stale findings file** whose scan was replaced. The page shows the scan
   without those findings and says why (Task 5).
5. **An agent with a small context window.** `inspect` output stays bounded
   (default 50 rows, compact columns) whatever the scan size (Task 4).

### Task 1: Score and rule-based recommendations

**Files:**
- Create: `src/storage_cleanup/scan/recommend.py`
- Test: `tests/scan/test_recommend.py`

**Interfaces:**

```python
@dataclass(frozen=True)
class Recommendation:
    item_id: str
    action: str           # "delete" | "archive"
    confidence: float     # 0..1
    reason: str           # one line a person can check
    source: str           # "rule" | "agent"

ACTIONS: Final = frozenset({"delete", "archive"})
def size_factor(size_bytes: int) -> float          # g(b) from Global Constraints
def score(confidence: float, size_bytes: int) -> float   # 100 * c * g, rounded to 1 decimal
def rule_recommendations(scan: Scan, now: float) -> list[Recommendation]
```

Rules (my calls; every one skips protected items, and only applies to items
present in the scan):

| Rule | Items | Action | Confidence | Reason text |
| --- | --- | --- | --- | --- |
| Known developer cache | kind `cache` with category `dev-caches` | delete | 0.9 | `"{why_safe} {regenerates}"` from details |
| Installer already installed | category `downloads` with `installer_for` | delete | 0.85 | `"Installer for {app}, which is already installed."` |
| Docker build cache | kind `docker-build-cache` | delete | 0.9 | `"Docker build cache; rebuilt when images are built again."` |
| Unused Docker image | kind `docker-image`, `containers == 0`, age ≥ 180 days | delete | 0.6 | `"Docker image no container has used in {age}."` |
| Rebuildable project folder | kind `regenerable` whose repo's last commit is ≥ 180 days old | delete | 0.7 | `"{pattern} in a project last committed {age} ago; rebuilt by its tools."` |
| AI sessions for a gone folder | kind `ai-sessions` with `cwd_exists` false | delete | 0.6 | `"{tool_name} sessions for a folder that no longer exists ({cwd})."` |
| Data from a removed app | category `leftover-app-data` | delete | 0.5 | `"Data left by {guessed_owner}, which is no longer installed."` |

`{age}` uses the same wording as the page ("14 months"). Write a small
`format_age(days) -> str` in `recommend.py` that matches `format.js`.

```python
FINDINGS_SCHEMA_VERSION: Final = 1

@dataclass(frozen=True)
class Headline:
    title: str; body: str; item_ids: tuple[str, ...]

@dataclass(frozen=True)
class AgentCategory:
    id: str; name: str; description: str; item_ids: tuple[str, ...]

@dataclass(frozen=True)
class Findings:
    schema_version: int
    scan: str                     # scan file name, e.g. "20261105T221259Z.json"
    created_at: str
    agent: str                    # free text, e.g. "Claude Code (claude-opus-5-5)"
    headlines: tuple[Headline, ...]
    categories: tuple[AgentCategory, ...]
    recommendations: tuple[Recommendation, ...]   # source == "agent"

def findings_dir(root: Path) -> Path                # root / "reports" / "findings"
def findings_path_for(scan_path: Path) -> Path      # <scan_path.parent.parent>/findings/<scan_path.name>
def parse_findings(text: str) -> Findings           # ValueError naming the first broken field
def validate_findings(findings: Findings, scan: Scan, scan_name: str) -> list[str]
    # empty list = valid; else one plain sentence per problem
```

Validation rules, each with its own message:
- `schema_version` is 1, and `scan` equals `scan_name` (`"These findings are for scan X, not Y."`).
- Every `item_id` (in headlines, categories, and recommendations) exists in the
  scan (`"Unknown item ID: ..."`).
- No recommendation for a protected item (`"Item ... is protected (<reason>) and cannot be recommended."`).
- `action` is in `ACTIONS`; `confidence` is a number from 0 to 1 inclusive.
- `reason` is non-empty and at most 200 characters. A headline `title` is at
  most 80 characters and `body` at most 300. There are at most 8 headlines.
- Category `id` matches `^[a-z0-9-]{1,40}$` and does not reuse a built-in
  category ID.
- No item is recommended twice.

CLI:

```
storage-cleanup findings path [--scan FILE] [--output-dir reports/scans]
    # prints the findings path for the latest (or given) scan
storage-cleanup findings check FILE [--scan FILE]
    # loads the scan the findings name (from the same reports/ tree) unless --scan is given;
    # prints "Findings are valid: N headlines, M recommendations." and exits 0,
    # or prints each problem on its own line and exits 1
```

### Task 3: Merge, roll-up, and recommendation page data

**Files:**

**Interfaces:**

```python
ROLLUP_MIN_ITEMS: Final = 3

def merge_recommendations(scan: Scan, rule: Sequence[Recommendation],
                          agent: Sequence[Recommendation]) -> list[Recommendation]
    # agent wins per item_id; drops unknown or protected items
def reclaimable_bytes(scan: Scan, recs: Sequence[Recommendation]) -> int
    # sum of sizes, counting an item only if no ancestor is also recommended
def recommendation_rows(scan: Scan, recs: Sequence[Recommendation], now: float
                        ) -> list[dict[str, JsonValue]]
```

Row fields: `id`, `item_id`, `name`, `path`, `size`, `age_days`,
`age_signal`, `category` (the category-tree group from `views.category_groups`),
`action`, `confidence`, `reason`, `source`, `score`, plus `children` for a
roll-up row. Rows are sorted by score, highest first.

**Roll-up** (spec section 7, my rule): when `ROLLUP_MIN_ITEMS` or more
recommended items share the same parent item and the same action, show them as
one row. That row's `id` is `rollup:<parent id>:<action>`, its name is
`"<n> items in <parent name>"`, its size is their summed size, its confidence
is their lowest confidence, and its score comes from those two values. Its
`reason` is the shared reason if all reasons are equal, else
`"<n> items; open to see each reason"`. The member rows go in `children`,
also sorted by score. A recommended item nested under another recommended item
is shown only under its ancestor's row (as a child row), so it is never counted
twice.

`build_view` gains:
`"recommendations": rows`, `"overview"."reclaimable_bytes"`,
`"findings": {"headlines": [...with item names/paths resolved...], "categories": [...],
"agent": str, "created_at": str} | None`, and `"findings_note": str | None`.

### Task 6: The playbook, and a real run of it

**Files:**
- Create: `AGENT_PLAYBOOK.md`
- Modify: `AGENTS.md` (one line under "Before Each Session" or a new "Analyzing a device" section linking the playbook), `README.md` ("Asking an agent to analyze your Mac")

Playbook contents (plain, numbered, short sentences, so any agent can follow it):

1. **Rules first.** Read-only. Never remove, move, or change files; never
   `sudo`; read-only commands from `AGENTS.md` only. The user acts in the page.
2. **Scan:** `uv run storage-cleanup scan` (about 3 minutes). Use
   `scan --path` for a folder you want measured in detail.
3. **Orient:** `uv run storage-cleanup inspect --summary`, then focused
   `inspect` queries per area: Downloads, AI tooling, Applications (by
   last-opened age), Homebrew and packages (leaves, install age), Docker,
   developer caches, projects, stray home folders. Give example commands for
   each.
4. **Investigate** what is large, old, or unexplained, with read-only commands
   (`ls`, `stat`, `du`, `mdls`, `brew info`, `git log`). Identify what a thing
   *is* before judging it.
5. **Decide confidence** with a rubric:
   - 0.9 or more: regenerates by itself, or is a duplicate of something kept.
   - 0.7: very likely unneeded, and easy to get back.
   - 0.5: probably unneeded, but the user should look.
   - Below 0.5: do not recommend; mention it in a headline instead if it is
     interesting.
   Choose `archive` over `delete` for anything personal or hard to recreate.
6. **Write headlines:** at most 8 cards, each a checkable fact with numbers.
   For example: "Your Downloads is mostly installers you already ran: 38
   files, 21 GB." Each card cites the item IDs behind it.
7. **Write the file** at the path from `storage-cleanup findings path`, using
   the JSON shape shown in full in the playbook (one complete example).
8. **Validate:** `uv run storage-cleanup findings check <file>`; fix
   everything it reports.
9. **Show the user:** `uv run storage-cleanup serve`, then tell them the three
   most useful findings in plain words.
